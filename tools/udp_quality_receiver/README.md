# 第二阶段：采集UDP时间质量接收工具

此工具接收实际采集UDP，区别于上位机v1.5.html的串口PTP记录。仅使用Python 3标准库，不需要pip依赖。

## 在哪台电脑运行

用户已授权改用当前电脑：IPv4 192.168.0.3，网卡MAC 00:E0:4C:20:52:28。需先完成管理员网络配置并加载soc_top_7.bit；第六版仍发向旧MAC 04:CB:01:DA:AA:DA。另一台电脑即使监听6000端口，也不保证能收到这些单播以太网帧。不要为此改动现有固件地址。

复制整个udp_quality_receiver目录到该电脑，确认安装Python 3，再双击启动接收.cmd。也可在本目录运行：

```powershell
py -3 receiver.py
# 限时5分钟，额外保存原始UDP数据（文件可能很大）
py -3 receiver.py --seconds 300 --raw
# 单独验证解析器，不需要开发板
py -3 -B test_receiver.py
```

监听UDP 6000，默认只记录来自192.168.0.14的包。运行前关闭占用同端口的其他收包程序；若系统防火墙提示，允许此Python程序接收当前测试网络的UDP流量。程序不自动更改网卡、防火墙或板卡。

控制台每秒显示累计各质量包数及最后一包的序号、时间戳、处理分类。Ctrl+C正常结束并保存summary.json。每个收到的包写入captures/capture_.../packets.csv；--raw另存raw_payloads.jsonl。控制台last字段也是最后收到的包，没有新包时不能把它当成当前时钟质量；计数不再增长表示没有收到新数据，不自动推断INVALID。

## 协议和处理策略

UDP载荷的每个16位字按大端字节发送，多字字段按低16位字在前。固定头20字节：word0=0x55AA；word1=版本和质量；word2/3=32位序号；word4=通道；word5=样本数；word6..9=64位时间戳。载荷长度必须等于20+2*样本数，零样本包也能解析。

| 协议/质量 | word1示例 | 分类 | 使用含义 |
| --- | --- | --- | --- |
| V1 UNKNOWN | 0x0001 | UNVERIFIED | 兼容旧包，不声称时间已锁定 |
| V2 INVALID | 0x0002 | ISOLATE | 留诊断记录，不能作为有效同步数据 |
| V2 REACQUIRE | 0x0102 | WAIT | 恢复中，等待时间质量恢复 |
| V2 LOCKED | 0x0202 | USE | 固件标记普通同步正常，并非精细锁定或独立精度证明 |
| V2 HOLDOVER | 0x0302 | RISK | 失去参考后守时，保留风险标记 |
| 格式错误 | 不适用 | MALFORMED | 留错误原因，不提供有效样本 |

这是验证接收器，只记录元数据和分类，不向后续计算发送样本。INVALID会留在诊断CSV中，默认有效数据应筛选disposition=USE；其余质量分别统计，不混成正常同步样本。保留完整64位整数时间戳；若用Excel导入，应将timestamp列设为文本，避免数值精度损失。未加入样本波形界面。

## 实板验收

1. 两板供电、正常联网：确认收到version=2、time_quality=LOCKED，时间戳和包序号更新。
2. 若方便，在交换机与PTP主板之间短暂断链，保留采集板到目标电脑的数据链路。结合串口原始日志观察守时/失效；短暂断链时不一定收到HOLDOVER包，取决于采集流启停与恢复策略。
3. INVALID后通常停流，因此“收不到INVALID包”并不表示标签功能失败。需结合串口和CSR/发送状态，已有队列里的旧质量包按包首状态解释。
4. 恢复连接后等到重新锁定，检查新UDP包恢复LOCKED。不要要求所有包在状态变化瞬间同步变色，质量按包首样本锁存。
5. 提供packets.csv、summary.json和同段串口原始日志；需要逐字节检查时增加--raw。不得用串口偏差CSV代替实际UDP验证。

当前工具测试仅证明主机解析/记录和本机回环收包。第六版真实包仍待目标电脑采集；FPGA构建时序违例仍未解决，不把接收工具测试当成硬件验收。
