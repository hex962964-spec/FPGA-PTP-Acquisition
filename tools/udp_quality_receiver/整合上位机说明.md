# 串口与UDP整合上位机

活动页面仍为工程根目录的上位机v1.5.html。新增本机服务dashboard_server.py，复用receiver.py中的V1/V2解析与记录，不改C/RTL/bit；继续使用第七版。

## 日常启动

双击工程根目录“启动整合上位机.cmd”。浏览器打开http://127.0.0.1:8765/，在原串口界面下方可见UDP面板。已有同一页面服务时重复启动会打开原服务，不再启动第二个。Windows需能找到Python 3（py或python）。本机服务只监听127.0.0.1。

直接双击HTML仍可使用串口，但UDP面板需从上述本机网址使用。浏览器会把file://和http://127.0.0.1:8765视为不同来源，因此第一次从新网址使用串口需要重新选择CH340并授权。先保存旧网页日志、断开旧页面串口，再在新页面连接。

1. 停止单独运行的旧UDP接收窗口，避免占用6000端口。网页串口与网口接收可以同时运行。
2. 点击“开始 UDP 记录”，它在后台监听192.168.0.3:6000，仅接收192.168.0.14；完整CSV自动保存到tools/udp_quality_receiver/captures。
3. 点击“停止并保存”完成CSV和summary；导出按钮下载所选记录的完整CSV。所有记录保留原有字段，序号和时间戳显示不会经过浮点数压缩。
4. “刷新记录列表”后选择以capture_开头的历史目录，再点击“分析所选记录”。支持本工程原来已有的记录。历史分析不会停止后台录制，结束测试需明确点击“停止并保存”。
5. 页面只保留最近50行、200条事件和最多1800秒聚合数据，流量图展示最近300秒；完整记录仍在CSV。查看历史不会把历史LOCKED当成当前状态。

关闭浏览器标签页不会停止记录。需先在页面点击停止；关闭本机服务控制台时Ctrl+C会尽力正常停止并保存。本次验证记录和服务管理信息在work/udp_dashboard_1。不要直接结束正在写入的进程，以免记录尾部丢失。

## 显示和解释

- 各质量包数分开统计，V1为UNKNOWN，V2无效包为INVALID并按原接收器分类ISOLATE，错误包MALFORMED。
- 超过1秒没有新包显示“未收到新包”，最后一包标历史；不据此伪造HOLDOVER/INVALID。
- 收包恢复时记录电脑测到的间隔，质量变化和序号回退另记事件。序号回退不等于已证明整板复位；缺口也不是已证明物理网络丢包的根因。
- 流量图按电脑收到数据的秒聚合，首尾秒可能只覆盖部分时间；不能作为独立对时精度测量。
- 单包timestamp用字符串传给浏览器，保留完整64位整数。串口时间质量和UDP最后一包质量分别展示，不混为同一个瞬时测量。
- 历史CSV与summary总数不一致时页面会提示；不会自动补造缺失行。

本次仅修改电脑端，没有新bit，不宣称修复FPGA时序违例，也没有新增实板HOLDOVER/INVALID切换验证。

最终版新增Windows HTTP端口独占，重复双击启动同一页面会复用服务；另一网页备份占用相同HTTP端口时明确报错，不隐式连接错误版本。第二版保留作历史，当前活动程序对应第三版配套依赖。


## 第四版网页：串口状态词与事件统计

新增“串口锁定与恢复事件统计”，自动解析实时串口和粘贴日志：
- LOCKED/HOLDOVER/INVALID/REACQUIRE各自显示进入次数（含首次观测）及关键词命中行数。关键词按每行去重，一行转移可命中两个词；进入次数按接受的状态变化计数，重复心跳不重复计入。
- fine_lock 0→1、1→0，stream 0→1、1→0分别统计精细锁定/退出和采集启用/停止。初次看到1计为首次观测，不能当成已测恢复耗时；首次只看到0不虚构退出事件。明确停流/启流日志也可建立状态，随后的心跳不会重复计数。
- 链路下降、稳定链路恢复及bringup round=0启动记录另计事件；启动记录并不证明物理断电。
- 累计次数独立于原始日志60 KB显示缓存；事件明细保留最近5000条，表格显示最近100条。导出事件CSV包含保留的明细，统计CSV含累计进入、关键词行数和动作次数。
- “清零事件统计”只清统计并保留当前状态作基线；串口“清空”、重新解析替换日志或刷新页面会清零。已有日志可在原“粘贴日志解析”区域导入。时间列为网页接收/解析时刻，导入旧日志不能作为真实发生时间或断网耗时。

该功能只修改HTML，不修改后台接收器、C/RTL或bit。继续使用第七版。活动文件名仍上位机v1.5.html，最终配套备份为bittest/4.web/上位机_4.html、sources_4、start_4.cmd/ps1。旧版完整保留。刷新前请保存当前串口日志和数据；UDP后台记录不会因为刷新自动停止。


## 第五版：关注状态标红与紧凑分页

- UDP质量计数实际大于0时，LOCKED绿色，HOLDOVER/REACQUIRE/INVALID/UNKNOWN/MALFORMED红色；0保持灰色。红色含义是需要关注，不等于所有这些包都应丢弃。旧质量值仍标为历史。
- 串口状态表、动作计数和事件行同步标色；退出精锁、停流、链路下降标红，恢复类事件绿色，未出现的状态灰色。
- PacketStats分别维护最近2000包与最近2000个非LOCKED关注包；后续正常包不会冲掉稀少的关注包。各类总数继续累计，完整数据仍写CSV；关注包超过2000条时也只保留最近2000条供页面查看。
- UDP包明细增加“只看关注状态”、每页50/100/200、上一页/下一页/回到最新。翻页期间冻结列表数据集，后台采集和总计数继续；切换记录、模式或回到最新解除冻结。表格区域保持原来的高度上限。
- 历史分析使用相同缓存规则，不声称页面可翻阅全部百万包；完整历史仍以CSV导出分析。原服务未重启时只会返回旧版50条缓存，需停止保存当前UDP再重启服务启用新缓存。

此版同时修改HTML与dashboard_server.py，仍不修改C/RTL/bit；继续使用第七版。配套备份为上位机_5.html、sources_5、start_5.cmd/ps1；旧版保留不覆盖。
